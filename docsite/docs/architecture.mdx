# Architecture

## Monorepo layout

```
evergreen-terrace/
├── core/                    Runtime services
│   ├── queue-server/        Bun HTTP server — queue lifecycle (port 2727)
│   ├── web/                 Vite/React dashboard (port 2728)
│   ├── metrics/             Append-only event log and analytics (port 2729)
│   ├── sentinel/            Health scoring server (port 2730)
│   ├── conductor/           Parallel agent orchestrator (port 2731)
│   ├── tui/                 Terminal dashboard
│   └── desktop/             Tauri v2 native app (optional)
├── packages/
│   ├── common/              Shared types and port constants (@evergreen-terrace/common)
│   └── config/              Shared TypeScript configs (@evergreen-terrace/config)
├── internal/
│   └── build-utils/         Bun.build() pipeline helpers
├── agents/                  Claude Code agent definitions (AGENT.md + agent.json)
├── skills/                  Shared knowledge bases loaded into agent system prompts
├── steering/                Global docs read by all agents
├── context/
│   ├── global.toml          Cross-project priority and sentinel state
│   ├── projects/            Per-project TOML files (one per managed project)
│   ├── metrics/             Append-only event log
│   ├── reports/             Sentinel run reports
│   └── beads/               Conductor goal/bead state
├── queue/
│   ├── inbox/               Pending work items (TOML files)
│   ├── active/              In-flight work items
│   └── completed/           Finished work items
├── scripts/                 Dev utilities (start.ts, tunnel.sh, sync-agents.ts)
├── .claude/workflows/       Model A and Model B execution guides
└── docsite/                 This documentation site
```

## Design principles

**Narrow scope per agent.** Each agent owns one lane. The PM agent doesn't touch code. The voice agent doesn't write tickets. Narrow scope produces predictable output and reduces review overhead.

**Persistent state over ephemeral state.** Everything that needs to survive a restart lives in TOML files on disk. Queue items, bead state, sentinel reports, project context — all disk-backed. Process restarts pick up where they left off.

**Human gates at phase transitions.** Agents produce drafts and proposals. You approve before work moves forward. The three gates: *what to build*, *how to build it*, *is it good enough to ship*.

**Working directory is load-bearing.** The conductor runs `claude -p` with `cwd` set to the project's repo path, resolved from the project's context TOML. Without this, agents run in the evergreen-terrace directory regardless of which project they're modifying. Every project TOML must have a `repo` field.

**Entry points own path resolution.** Shared config holds only structural constants — ports, type definitions. Filesystem paths are resolved once at startup in each service's entry point using `process.env.QUEUE_ROOT ?? process.cwd()`. This survives bundling.

**Voice transform on external output.** The `voice` agent rewrites AI-generated content from the substance up before anything goes out.

## Agent system prompt assembly

When the conductor (or any invocation via `buildSystemPrompt`) assembles an agent's context:

1. Read `agents/{role}/AGENT.md`
2. For each skill in `agent.json skills[]`: read `skills/{skill}/SKILL.md`
3. For each doc in `agent.json steering[]`: read `steering/{doc}.md`
4. For conductor-dispatched beads: append project context TOML + conductor-mode instruction

The assembled prompt is passed to `claude -p --system-prompt "..."`.

## Package dependency graph

```
@evergreen-terrace/queue-server
  @evergreen-terrace/common     (QueueItem, QueueState, config)
  toml                          (TOML parsing)

@evergreen-terrace/sentinel
  @evergreen-terrace/common
  toml

@evergreen-terrace/conductor
  @evergreen-terrace/common
  toml

@evergreen-terrace/dashboard    (core/web)
  @evergreen-terrace/common
  react, react-dom, recharts
```

`@evergreen-terrace/common` is the single source of truth for shared types and port constants. No package duplicates these.

## TypeScript configuration

All packages extend the root `tsconfig.json` via `@evergreen-terrace/config`:

```json
{
  "module": "Preserve",
  "moduleDetection": "force",
  "verbatimModuleSyntax": true,
  "noUncheckedIndexedAccess": true,
  "noImplicitOverride": true,
  "strict": true
}
```

`verbatimModuleSyntax` enforces `import type` for type-only imports. `noUncheckedIndexedAccess` catches array/object access bugs at compile time. These are non-negotiable.

## Build pipeline

```
typecheck ← build
```

Each `core/` package has a `Bun.build()` pipeline (`build/index.ts`) that produces `dist/index.js`. The `start` script runs compiled `dist/` output. The `dev` script runs source directly via `bun --watch`.

The web dashboard uses Vite for development and production builds.
