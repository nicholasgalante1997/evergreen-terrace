# Work Queue

The work queue is the operational backbone of evergreen-terrace. It tracks every piece of work as TOML files on disk, served over a lightweight HTTP API. The web dashboard is the primary interface; the API is available for scripting and integration.

## Lifecycle

```
queue/inbox/   →   queue/active/   →   queue/completed/
    ↑                   ↑
    └── return ─────────┘
```

Items enter the inbox from four sources: manual TOML files, the PM agent, sentinel findings, or external integrations (Jira, GitLab). Dispatching an item moves it atomically from `inbox/` to `active/`. Completing it moves it to `completed/`. Returning it moves it back to `inbox/`.

## Data model

Each work item is a TOML file with three sections:

```toml
[item]
id = "a4f1c8d2-3b7e-4a09-9e5f-bc2301847601"  # UUID
title = "deck-cli: stress test and spec acceptance verification"
project = "deckvault"                           # must match context/projects/{name}.toml
type = "ops"                                    # feature | bug | research | design | pm | ops
priority = "p0"                                 # p0 | p1 | p2 | p3
created = "2026-05-08T00:00:00"                 # ISO datetime
source = "sentinel"                             # manual | sentinel | jira | gitlab

[delegation]
agent = "eng-mid"        # which agent handles this
delegated_at = ""        # set by queue-server when dispatched

[context]
description = """
Full context for why this work exists, what the current state is,
and any background the agent needs.
"""
acceptance = """
- [ ] cargo clippy -- -D warnings is clean
- [ ] cargo test passes with no regressions
- [ ] ./dist/johto.mjs --help prints usage
"""
links = [
  ".claude/specs/deck-cli/OVERVIEW.md",
  "apps/deck-cli/src/"
]
```

### Priority levels

| Priority | Meaning                                            |
| -------- | -------------------------------------------------- |
| `p0`     | Drop everything — blocking or production-impacting |
| `p1`     | High — active development, should move this week   |
| `p2`     | Medium — scheduled work, will get to it            |
| `p3`     | Low — backlog, nice to have, or explicitly parked  |

### Item types

| Type       | Used for                                                     |
| ---------- | ------------------------------------------------------------ |
| `feature`  | New functionality — triggers review gate in conductor        |
| `bug`      | Defect or regression — triggers review gate                  |
| `ops`      | Infrastructure, tooling, config — triggers review gate       |
| `pm`       | Planning, PRDs, backlog work — auto-completes in conductor   |
| `research` | Investigation, spike, analysis — auto-completes in conductor |
| `design`   | Design specs, Figma work — review gate enabled by default    |

The review gate means: when the conductor finishes executing a `feature`, `bug`, or `ops` ticket, the bead enters `review_pending` status and requires your explicit approval before the item is marked complete. This allows you to review the diff before anything is counted as done.

## Queue server API

Runs on `http://localhost:2727`.

### Read endpoints

| Method | Path               | Description                                |
| ------ | ------------------ | ------------------------------------------ |
| `GET`  | `/health`          | `{ ok: true }`                             |
| `GET`  | `/queue`           | Full state: `{ inbox, active, completed }` |
| `GET`  | `/queue/inbox`     | Pending items only                         |
| `GET`  | `/queue/active`    | In-flight items only                       |
| `GET`  | `/queue/completed` | Completed items                            |

### Mutation endpoints

**`POST /queue/delegate`** — move inbox → active, assign agent, fire conductor

```json
{ "id": "a4f1c8d2-...", "agent": "eng-mid" }
```

Returns `{ "ok": true }`. Also notifies the conductor to start work if it is running.

**`POST /queue/complete`** — move active → completed

```json
{ "id": "a4f1c8d2-..." }
```

Called automatically by the conductor when approving a bead. Can also be called manually.

**`POST /queue/return`** — move active → inbox

```json
{ "id": "a4f1c8d2-..." }
```

Used when work needs to be re-evaluated or the agent assignment needs to change.

## Path resolution

The queue server resolves file paths from `QUEUE_ROOT` (env variable, defaults to `process.cwd()`). Set this to the absolute repo root:

```sh
QUEUE_ROOT=/home/nicks-dgx/dev/evergreen-terrace
```

## Dashboards

### Web dashboard

The primary interface. Three-pane layout: sidebar item list, center detail panel, right agent feed. See the [User Manual](https://github.com) or `USER_MANUAL.md` in the repo root for a full walk-through.

### Terminal dashboard (TUI)

```sh
bun run tui
```

Priority-colored list view. Press `r` to refresh, `q` to quit. Useful for a quick health check from the terminal without opening a browser.
