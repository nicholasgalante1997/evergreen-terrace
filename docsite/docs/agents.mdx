# Agents

Eight role-scoped agents, each owning one lane. Narrow scope produces predictable output and reduces review overhead. Agents produce drafts and proposals — you approve before anything ships.

All agents live in `agents/` as a pair of files:
- `AGENT.md` — full instructions for the role
- `agent.json` — conductor config: model, allowed tools, skills, steering references

They are installed globally to `~/.claude/agents/` and available in any Claude Code session. The conductor uses them when executing queue items.

## Invoking agents

**From a Claude Code session:** mention the agent role in your message, or use `/agent-name` if Claude Code supports slash commands for registered agents.

**From the conductor:** happens automatically when a queue item is dispatched — the item's `delegation.agent` field determines which agent runs.

**Manual sync** (after editing `agents/`, `skills/`, or `steering/`):

```sh
bun run sync-agents
# or: mise run sync-agents
```

## PM lane

### `pm` — Product Manager

Turns rough ideas, stakeholder asks, or problem statements into structured tickets. Writes TOML files directly to `queue/inbox/`.

**Does:**
- Clarifying questions (two rounds max), then produces a ticket
- Breaks goals into multiple atomic tickets
- Backlog review and prioritization against `context/global.toml`
- Ticket grooming — identifies missing acceptance criteria

**Does not:** Make architectural decisions. Estimate timelines. Touch code.

**Model:** `claude-sonnet-4-6`  
**Tools:** `Read, Write, Bash, Grep, Glob`

---

### `stakeholder` — Stakeholder Communication

Translates technical work into business language. Writes status updates, escalation summaries, and executive-facing content.

**Does:**
- Status updates (done / in-progress / blocked / next)
- Escalation summaries — situation, impact, ask, consequence of inaction
- Business language translation — outcomes, not implementation details

**Does not:** Spin bad news. Make commitments. Use jargon without translation.

**Output:** Route through `voice` before delivery.

**Model:** `claude-sonnet-4-6`  
**Tools:** `Read, Write, Bash, Grep, Glob`

---

### `director` — Director-Level Challenge

Adversarial by design. Applies scope pressure and stress-tests decisions.

**Does:**
- Scope pressure — finds the minimum version that delivers core value
- Prioritization challenge — identifies weakest justification vs. highest impact
- Decision stress-test — surfaces assumptions and opportunity cost
- Delivery reality check — most likely slip, dependency risks

**Does not:** Make product decisions. Override your final call.

**Model:** `claude-sonnet-4-6`  
**Tools:** `Read, Grep, Glob`

## Engineering lane

### `eng-senior` — Senior Engineer

Owns architecture decisions, PR review, and technical design. Reads the codebase before writing anything.

**Does:**
- Architecture decisions with explicit tradeoffs
- PR/MR review against established standards
- Technical design — what files change, what the data flow looks like
- ADR authoring
- Spec handoff to `eng-mid`

**Does not:** Write boilerplate. Implement from a clear spec. Make product decisions.

**Model:** `claude-opus-4-7`  
**Tools:** `Read, Write, Edit, Bash, Grep, Glob`

---

### `eng-mid` — Mid-Level Engineer

Implements features from a clear spec. Follows existing patterns, produces working code.

**Does:**
- Feature implementation from spec
- Component and API handler implementation
- Pattern-following — reads existing code first, matches conventions
- Test writing for implemented features

**Does not:** Make architectural decisions. Merge or push.

**Model:** `claude-sonnet-4-6`  
**Tools:** `Read, Write, Edit, Bash, Grep, Glob`

---

### `eng-junior` — Junior Engineer

Handles boilerplate, test writing, scaffolding, and repetitive tasks. Does exactly what was asked — nothing more.

**Does:**
- Package scaffolding
- Test writing
- Barrel export updates
- Type definition files
- Repetitive implementation from a reference pattern

**Does not:** Make decisions. Refactor out-of-scope code. Add dependencies.

**Model:** `claude-sonnet-4-6`  
**Tools:** `Read, Write, Edit, Bash, Grep, Glob`

## Voice lane

### `voice` — Human-Readable Transform

Rewrites AI-generated content in Nick's natural written register. Not a polish pass — a rewrite from the substance up.

**Contexts:** `email` · `webex` · `pr-description` · `jira-ticket` · `stakeholder-update` · `technical-doc` · `blog-post`

**Strips on sight:** hedging qualifiers, passive voice where active works, filler phrases like "It's worth noting", bullet points for prose content.

**Loads:** `skills/nick-voice/` before every session.

**Model:** `claude-sonnet-4-6`  
**Tools:** `Read, Write, Bash, Grep, Glob`

## Sentinel

### `momentum-sentinel` — Project Health Monitor

Reads the persistent context layer, scores each project on four dimensions, and produces a ranked report. Called by the sentinel service via `claude -p`.

**Scoring (0–100):**

| Dimension | Max | Signal |
|-----------|-----|--------|
| Activity | 25 | Git commit recency |
| Queue Health | 25 | Inbox size and blocked items |
| Priority Alignment | 25 | Stated priority vs. actual activity |
| Context Freshness | 25 | Age of `last_touched` in project TOML |

**Score interpretation:** 75–100 healthy · 50–74 at-risk · 0–49 stale

**After each run:** Updates `sentinel.last_run` in `context/global.toml` and `health` in each project TOML.

**Does not:** Create tickets. Modify source code. Change `priority` or `manual_override` fields.

**Model:** `claude-sonnet-4-6`  
**Tools:** `Read, Bash, Grep, Glob`
