# Skills

Skills are shared knowledge bases that agents load into their system prompts. They live in `skills/{name}/SKILL.md` and are referenced in each agent's `agent.json`. A skill is read at invocation time — the conductor reads them when building the system prompt for a bead execution.

## `nick-voice`

**Path:** `skills/nick-voice/SKILL.md`  
**Used by:** `voice`, `pm`, `stakeholder`

The voice model for Nick's written register. Built from writing samples across emails, technical documentation, and blog posts.

Covers sentence structure, register, direct opinion-stating patterns, what to strip from AI-generated output (filler phrases, passive voice, over-structured responses), and format rules by context type (email, PR description, stakeholder update, blog post).

## `nick-conventions`

**Path:** `skills/nick-conventions/SKILL.md`  
**Used by:** `eng-senior`, `eng-mid`, `eng-junior`, `pm`

Code conventions observed across the active project portfolio. Engineering agents load this before generating any code.

Covers runtime (Bun-first), TypeScript conventions (interfaces, imports, error handling, async patterns), React patterns (functional only, `React.memo`, vanilla CSS BEM), CLI patterns, file structure, and what to avoid (`any` types, default exports for utilities, inline styles).

## `bundt-context`

**Path:** `skills/bundt-context/SKILL.md`  
**Used by:** `eng-senior`, `eng-mid` (when working on bundt packages)

Deep context for the `bundt` OSS tooling monorepo (`~/dev/bundt`). Read before any task touching `@bundt/*` packages.

## Adding a skill

Create `skills/{name}/SKILL.md` with structured domain knowledge. Then add the skill name to the relevant agent's `agent.json`:

```json
{
  "skills": ["nick-conventions", "your-new-skill"]
}
```

Run `bun run sync-agents` to push the updated agent definition to `~/.claude/agents/`.
