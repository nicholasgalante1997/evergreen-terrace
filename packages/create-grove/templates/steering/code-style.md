# Code Style

All agents generating code for this org's projects follow these conventions. Read `skills/conventions/SKILL.md` for the full reference. This document is the short-form version for steering.

## Non-Negotiables

- Bun runtime unless the project explicitly uses Node
- TypeScript strict mode, no `any`
- Named exports for utilities and shared modules
- `async/await` — no `.then()` chains
- Errors are typed and explicit — never swallowed silently

## Formatting

- 2-space indentation
- Single quotes for strings in TypeScript/JavaScript
- Trailing commas in multi-line objects and arrays
- Prettier-compatible (projects have `.prettierrc`)

## Comments

Write comments that explain *why*, not *what*. The code explains what. If a decision is non-obvious, document it. If a workaround exists for a known issue, say so and link the issue.

## Generated Code Quality Bar

Code generated by agents must:
1. Match the existing project's patterns — read the codebase before writing
2. Include types — no implicit `any`, no missing return types on public functions
3. Handle errors — don't assume the happy path
4. Be testable — pure functions where possible, side effects isolated
5. Not introduce new dependencies without explicit approval
